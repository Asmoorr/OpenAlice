## Why

OpenAlice уже реализует ключевой сценарий голосового моста, но HTTP-слой, управление жизненным циклом, прикладная логика, конкурентность и создание инфраструктурных зависимостей сосредоточены в `app.py`, а `Store` одновременно является контрактом хранения и SQLite-реализацией. Это усложняет изолированное тестирование, провоцирует разрастание временных каталогов, оставляет ручные API-проверки неполными и делает эксплуатационные инструкции трудными для сопровождения.

## What Changes

- Разделить приложение на presentation, application, domain и infrastructure с направлением зависимостей к внутренним слоям и отдельным composition root.
- Выделить типизированные порты для Gateway, репозиториев, уведомлений, выбора фразы ожидания и времени; сохранить текущие HTTP-контракты, команды, дедупликацию, поколения диалогов, быстрый и отложенный ответы.
- Применять паттерны только в местах реальной вариативности: Adapter для внешних систем, Strategy для уведомлений, фраз ожидания и retry policy, Command для служебных команд, Repository для хранения и Factory/composition root для сборки приложения.
- Настроить один управляемый каталог `.test-tmp`, безопасную очистку до/после тестового запуска и единый тестовый entry point без создания каталогов `.test-tmp-*`.
- Расширить Bruno-коллекцию сценариями health, webhook, команд, дедупликации, авторизации, быстрого и отложенного ответа; удалить секрет из отслеживаемого запроса и получать чувствительные значения только из локального окружения Bruno.
- Сократить README до быстрого старта и карты документации, а подробности перенести в тематические документы `docs/` без дублирования.
- Добавить изолированные unit-тесты для application/domain-компонентов и адаптеров, отдельные интеграционные тесты SQLite и HTTP-контрактов, отчёт покрытия и обязательный порог покрытия.
- Добавить статические проверки форматирования, lint и типов, а также единый локальный quality-check.
- Выполнить работу серией небольших русскоязычных Conventional Commits, не смешивая инфраструктуру тестов, архитектурные переносы, Bruno, документацию и усиление качества.

## Capabilities

### New Capabilities

- `clean-application-architecture`: Границы слоёв, порты и адаптеры, composition root и гарантии сохранения поведения webhook при рефакторинге.
- `test-workspace-management`: Единый временный каталог тестов, контролируемая очистка и отсутствие размножающихся `.test-tmp-*`.
- `bruno-api-scenarios`: Безопасная Bruno-коллекция с воспроизводимыми ручными сценариями OpenAlice и OpenClaw.
- `project-documentation`: Краткий README и тематическая структура документации с единым источником истины.
- `automated-quality-verification`: Unit-, integration- и contract-тесты, измеримое покрытие и статические проверки проекта.

### Modified Capabilities

Нет: в проекте пока отсутствуют основные OpenSpec-спецификации, а внешнее поведение существующего приложения должно быть сохранено.

## Impact

- Основные затронутые области: `openalice/app.py`, `openalice/store.py`, `openalice/openclaw_client.py`, `openalice/commands.py`, `openalice/notifications/`, `openalice/glagol.py`, конфигурация и новые пакеты слоёв приложения.
- Тесты будут реорганизованы по уровням; появятся недостающие тесты хранилища, Gateway-клиента, конфигурации, преобразования текста, моделей и прикладных use case.
- Изменятся `pyproject.toml`, тестовый PowerShell-скрипт, `.gitignore`, `bruno/`, `README.md` и новые материалы `docs/`.
- Публичные маршруты, формат Алисы, дедлайн webhook, стабильный `user` OpenResponses и правила отложенного ответа остаются совместимыми.
- Потребуются новые dev-зависимости для coverage, lint и проверки типов; runtime-зависимости не должны расширяться без необходимости.
- Отслеживаемый bearer-токен Bruno должен быть удалён из файлов и отозван оператором, поскольку очистка текущей версии не аннулирует уже раскрытый секрет и не удаляет его из истории Git.
- Существующее незакоммиченное изменение таймаута в `openalice/openclaw_client.py` считается пользовательской работой и должно быть сохранено либо включено в подходящий отдельный коммит только с явным подтверждением владельца.
