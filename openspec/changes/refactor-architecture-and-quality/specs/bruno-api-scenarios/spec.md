## Purpose

Определяет безопасную и воспроизводимую Bruno-коллекцию для ручной проверки публичного API OpenAlice и диагностического вызова локального OpenClaw Gateway.

## ADDED Requirements

### Requirement: Секреты вне репозитория
Bruno-коллекция MUST получать webhook secret, Gateway token и другие чувствительные значения из локальных переменных окружения и MUST не содержать реальные секреты в отслеживаемых файлах.

#### Scenario: Проверка репозитория на секреты Bruno
- **WHEN** разработчик просматривает все отслеживаемые файлы Bruno
- **THEN** в них отсутствуют bearer-токены и реальные значения webhook secret

#### Scenario: Запуск без локального секрета
- **WHEN** обязательная локальная переменная Bruno не задана
- **THEN** соответствующий запрос не отправляется с фиктивным встроенным секретом и выдаёт понятную ошибку настройки

### Requirement: Покрытие публичных сценариев OpenAlice
Коллекция SHALL содержать именованные запросы для health, открытия навыка, обычного вопроса, help, result, cancel, new dialog, exit, неверного секрета, запрещённого пользователя, повторной доставки и отложенного ответа.

#### Scenario: Ручная smoke-проверка
- **WHEN** OpenAlice запущен в fake mode и разработчик выполняет smoke-папку коллекции
- **THEN** health, открытие навыка, обычный вопрос и основные команды проверяются без обращения к реальному Gateway

#### Scenario: Проверка отложенного ответа
- **WHEN** fake mode настроен с задержкой больше быстрого дедлайна
- **THEN** последовательность запросов проверяет фразу ожидания, последующую команду result и получение готового ответа

### Requirement: Проверяемые ответы
Каждый стабильный Bruno-сценарий SHALL содержать автоматические проверки HTTP-статуса и ключевых полей ответа, а последовательные сценарии SHALL переиспользовать согласованные идентификаторы сессии и увеличивать `message_id`.

#### Scenario: Нарушение контракта ответа
- **WHEN** API возвращает неожиданный статус или структуру JSON
- **THEN** тест Bruno завершается неуспешно с указанием нарушенной проверки

### Requirement: Разделение OpenAlice и Gateway
Диагностический запрос к OpenClaw Gateway SHALL быть отделён от публичных сценариев OpenAlice и SHALL быть явно помечен как требующий запущенного локального Gateway и операторского токена.

#### Scenario: Запуск только публичных сценариев
- **WHEN** разработчик выполняет коллекцию OpenAlice без Gateway credentials
- **THEN** диагностический Gateway-запрос не является обязательным для успешного завершения набора OpenAlice
